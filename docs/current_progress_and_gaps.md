# 当前进度、成熟度与真实可用差距

> 更新日期：2026-08-20
>
> 本文是当前状态的唯一摘要入口。P0-P8 表示仓库内软件工程交付阶段，V0-V7 表示证据
> 等级。二者不能混用。闭环能运行不等于模型可信，更不等于可用于真实型号结论。

## 1. 结论

项目已经形成可重复、可回放、可批量的软件在环闭环工程基线，不再是只演示运动方程的
最小样例。仓库内 P0-P8/V0-V5 的验收入口已闭合，包括双进程协议、6DOF、传感器、故障、
飞控任务链、多实例、回放、Monte Carlo、运行清单、性能统计和自动测试。

项目目前仍不是“真实型号仿真器”或“合格飞控软件”。阻止真实交付的核心问题不是再增加
几个代码模块，而是缺少目标对象数据、标定、外部相关性、真实接口和独立 V&V。当前命中、
脱靶量、控制品质和实时裕度只能用于本仓库模型内的工程回归，不能外推为实物性能。

## 3. 已闭合的仓库内主链路

- `SIL_FAST`、`SIL_REALTIME`、`LOCKSTEP` 和 `FREE_RUNNING` 已进入双进程闭环。
- `REPLAY_PASSIVE`、`REPLAY_WITH_FC` 和 `MONTE_CARLO` 会生成独立运行清单，记录输入、
  CRC、软件身份、种子来源、帧/样本数量和结果。
- 环境侧已接入 WGS-84/ECEF、Euler/RK2/RK4、6DOF、质量/质心/完整惯量演化、重力、
  ISA 大气、风切变/阵风/确定性湍流、推进、低阶/v1/v2/线性代理气动和执行机构。
- 目标模型已区分 `CONSTANT_VELOCITY` 与带 ECEF 加速度段的 `SCRIPTED_ACCELERATION`，
  步内机动边界分段积分；命中判定使用步间连续相对线段，避免高速穿越漏判。
- 传感器支持多率采样、保持、偏置、白噪声、随机游走、量化、限幅、固定延迟和丢包。
- 故障矩阵覆盖传感器偏置/漂移/斜坡/噪声增大/丢包/起点卡滞/动态延迟/饱和，执行机构
  卡滞/偏置/速率退化/行程退化/延迟/失能，以及报文丢弃/延迟/重复/损坏/乱序。
- 飞控侧已接入协议校验、导航/估计、模式和健康状态机、三维 PNG、姿态/角速度自动驾驶仪、
  控制分配、命令限幅/变化率限制、安全保护和固定格式内部日志。
- 每次环境和飞控运行保存配置字节快照、CRC、Git/编译身份、协议、运行/同步模式、日志路径、
  未识别配置字段和性能统计；正常结束使用协议停止帧，不依赖接收超时回收飞控。
- 11 个默认 CTest 覆盖公共库、环境、飞控、闭环、多实例、回放、日志、地图、批跑、控制品质
  和 4 实例短压力；16 和 128 实例压力层可显式开启。

## 4. 与成熟仿真平台的关键差距

### 4.1 阻塞真实型号结论的 P0 缺口

1. **目标外形气动数据**：v1/v2 表和 surrogate 机制已具备，但没有目标对象 CFD、风洞或
   经批准公开数据库，也没有跨工具相关性和不确定度预算。
2. **推进与质量属性标定**：推力、燃速、质心和惯量模型可运行，但没有发动机台架、称量和
   惯量测试数据，也没有批次/温度/制造散差模型。
3. **传感器与执行机构器件模型**：已有通用误差和故障链，参数不是来自具体 IMU、导引头、
   舵机或电源系统的标定数据；缺少温漂、轴间耦合、安装误差和器件级非线性证据。
4. **真实飞控软件和硬件接口**：当前是研究控制律模拟件，不是目标处理器上的生产飞控代码；
   没有总线驱动、I/O 时序、量化定点、编译器/处理器差异、HIL 或故障安全台架证据。
5. **外部相关性与独立 V&V**：尚未与权威 6DOF 工具、解析基准、试验弹道或飞行数据完成
   盲测相关性；没有独立团队签署的需求追踪、测试见证和模型认可记录。

### 4.2 影响工程规模化的 P1 缺口

- 大气仍以 ISA 和工程风模型为主，缺少 GRAM/数值天气、复杂湍流谱、结冰/降水等环境库。
- 重力和地球环境缺少高阶重力场、地球定向、时变环境以及严格时间基准体系。
- 目标模型已有脚本加速度段，但缺少完整目标飞行动力学、航迹/行为库和多对象场景管理。
- baseline 仍使用 ECEF 加速度级虚拟执行机构；真实舵面铰链力矩、气动伺服弹性、结构/热和
  推力矢量模型尚未建立。
- 导航估计是工程简化实现，缺少经过传感器模型标定的 INS/GNSS/导引头融合滤波、协方差一致性、
  可观测性和失效隔离验证。
- 只支持本机进程编排；没有 HLA/DIS/FMI、远程节点、资源配额、分布式时钟和集群结果管理。
- 缺少成熟平台常见的场景 GUI、三维可视化、交互调试、参数数据库、权限审计和结果资产管理。
- 当前软实时统计不是 WCET 分析；还缺 CPU 亲和性、优先级、内存锁定、调度抖动和目标硬件基准。

## 5. 真实可用的完成门槛

“真实可用”必须针对具体用途签署，不使用单一百分比。至少需要：

1. 冻结目标对象、任务包线、坐标/单位、输入数据版本和允许误差。
2. 为气动、推进、质量、传感器和执行机构建立数据来源、标定报告、适用包线和不确定度预算。
3. 选择独立参考工具或解析/试验数据，定义逐状态和任务指标的相关性阈值，并完成 V6。
4. 将目标飞控二进制或同源代码接入真实接口，完成正常、边界和故障场景 HIL/台架验证。
5. 在目标计算平台完成长时稳定性、WCET、资源上限、异常恢复和数据完整性测试。
6. 建立需求到模型、代码、测试、报告的双向追踪，以及配置基线、变更控制和独立审查。
7. 只有上述证据通过后，才能把特定配置声明为某个用途的合格仿真基线。
