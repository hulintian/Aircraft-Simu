# 与主流飞行仿真软件的差距调研

> 更新时间：2026-08-20
> 本文用于给项目新成员建立外部参照系：本仓库是什么、不是什么，
> 和成熟飞行仿真/任务仿真软件相比差在哪里，后续应优先补什么。

## 1. 结论摘要

本项目是一个面向飞控闭环验证、具有 V0-V5 自动证据的软件在环（SIL）工程基线，而不是通用飞行
模拟器或完整任务工程平台。它的优势是代码小、边界清楚、双进程隔离实际存在、
协议和日志可回放、多实例可批量运行；短板是目标型号物理相关性、真实数据资产、
可视化、模型生态、HIL/分布式集成和认证级工具链都还远弱于成熟软件。

最接近的外部参照不是娱乐飞行模拟器，而是：

- JSBSim：开源飞行动力学模型库，强调可配置飞行器、控制系统和批处理。
- NASA Trick：通用仿真开发框架，强调调度、输入、记录和 V/HIL 基础设施。
- MathWorks Aerospace Blockset：模型化、高保真组件库、GNC、HIL 和可视化生态。
- FlightGear / X-Plane / Microsoft Flight Simulator：大规模场景、飞行体验、插件和视觉生态。
- Ansys STK：系统级、多域任务工程、关系几何、报告和可视化。

## 2. 参照软件概览

| 软件 | 定位 | 强项 | 对本项目的启发 |
|---|---|---|---|
| JSBSim | 开源 C++ 飞行动力学模型 | XML 飞行器定义、质量/推进/气动/控制系统、批处理、可配置日志 | 应把气动/质量/推进/控制律参数继续数据化，减少写死在代码里的模型形状 |
| FlightGear | 开源通用飞行模拟框架 | 场景、飞机模型、可扩展系统、研究/教学/桌面模拟用途 | 本项目缺少可视化、飞机/任务生态和用户交互层，不应和它拼“完整模拟器” |
| X-Plane | 商业飞行模拟器 | Blade element flight model、几何驱动力/力矩构建、桌面体验 | 本项目当前仍以表/代理/低阶气动为主，尚无按几何元素构建全机气动力 |
| Microsoft Flight Simulator | 商业沉浸式飞行模拟器 | 全球场景、实时天气、图形、航空职业/任务体验、复杂飞机系统 | 本项目没有大规模视觉/天气/座舱系统，目标应保持工程验证而不是娱乐体验 |
| Aerospace Blockset | 商业模型化工程工具 | 高保真航空/航天组件、环境模型、GNC、SIL/HIL、Unreal/FlightGear 可视化 | 本项目需要补模型库、数据管理、自动报告和 HIL 接口，才能接近工程平台 |
| NASA Trick | 通用仿真框架 | 调度、输入文件、数据记录、V/HIL、训练和飞软开发基础设施 | 本项目可借鉴其“仿真基础设施”和“领域模型分离”的设计方向 |
| Ansys STK | 数字任务工程平台 | 多域场景、任务关系几何、RF/传感器/空间/空中任务分析、报告 | 本项目当前只覆盖单目标闭环，缺少任务级多对象、多传感器、多约束分析 |

## 3. 关键差距

### 3.1 动力学与气动保真度

本项目已经具备 ECEF/LLA、6DOF 状态、质量、推进、大气、重力、简化气动、气动表
和线性 surrogate 的接口，但仍主要是“工程骨架 + 低阶可替换模型”。成熟 FDM 通常
拥有大量经验证的飞行器配置、气动导数、控制面模型、发动机/燃油/起落架/地面效应
等模型库。

当前差距：

- 没有真实飞行器数据集和验证基准。
- v1 和六维 v2 气动表、线性 surrogate 都已接入，但系数仍不是目标外形 CFD/风洞数据。
- 精细质心/完整惯量演化已具备接口和回归，参数仍是工程基线而非真实质量属性数据。
- 控制品质标准机动已能验收工程链路，但没有真实对象带宽、稳定裕度和包线基准。

优先补强：

1. 建立非敏感、公开来源或合成的基准飞行器数据包。
2. 用目标外形数据填充 v2 六维表，并与独立工具做 V6 交叉验证。
3. 用真实质量属性、执行机构和控制品质指标替换工程参数。

### 3.2 场景、地形和环境

本项目已有 WGS-84、内部瓦片、ESRI ASCII Grid、SRTM HGT 预处理、AGL、碰撞和
LOS 遮挡，但 baseline 仍使用 `FLAT_FILL`。仓库已有带来源和 SHA-256 的真实来源最小
DEM fixture，不包含全球或任务区域完整数据。成熟桌面或
任务仿真软件通常有全球地形、影像、机场、天气、传感器场景和可视化资产。

当前差距：

- 没有生产级大范围 DEM/影像资产和持续更新的数据目录。
- 固定槽位磁盘懒加载 LRU 和资源 manifest 已有，但不是全球地图资源管理系统。
- 已有风切变、阵风和确定性湍流，没有天气、云雨和能见度模型。
- 已有报告级轨迹/诊断绘图，没有沉浸式三维场景或任务态势系统。

优先补强：

1. 为目标任务区域建立完整 DEM 资源包、许可证、版本和生成流水线。
2. 在目标机器验证大范围瓦片访问、缓存命中和长时资源占用。
3. 引入权威风场/天气数据并完成适用范围验证。

### 3.3 飞控、传感器和故障

本项目的飞控链路比普通演示项目更完整：安全监控、导航估计、状态机、PNG、
自动驾驶仪、命令管理、限幅/变化率、旧帧/NaN/超时/无效测量保护都进了主链路。
但成熟工程工具会提供更广的传感器库、故障库、时钟/总线/调度模型和 HIL 接口。

当前差距：

- 传感器只有 IMU、加速度计、速度计、导引头和派生地理量。
- 故障矩阵已覆盖传感器、执行机构和报文丢弃/延迟/重复/损坏/乱序，`FREE_RUNNING`
  已验证损坏报文拒绝和后续恢复；尚未建立真实网络栈/总线时序相关性模型。
- 飞控内部日志已有正式 CSV 解码和控制品质 JSON 报告，但没有型号级自动诊断规则库。
- 没有真实飞控软件接口、硬件总线或 HIL 适配层。

优先补强：

1. 在协议 v2 中增加每传感器独立时间戳、时钟域和异步队列语义。
2. 对接真实总线或网络适配层，验证非锁步抖动、乱序和恢复。
3. 用真实器件数据标定传感器安装误差、漂移和采样时序。

### 3.4 批量验证、回放和工程工具链

本项目在回放和批量验证方面已经有较好基础：二进制日志、`replay`、`compare_logs`、
`batch_stats`、`batch_runner`、LHS/Halton/正态/截断正态/相关正态采样和多实例管理。
回放、转换和 Monte Carlo 工作流均保存带 CRC、构建身份和结果状态的 sidecar manifest。
成熟平台更强的是报告、数据库、可视化、参数管理、需求追踪和持续集成矩阵。

当前差距：

- 已有验证指南、控制品质 JSON 和专业 PNG，但没有统一 HTML/数据库报告门户。
- 已有二进制/轨迹精确比较和版本化容差策略，没有长期基准产物仓库和审批流程。
- 已有 4/16/128 实例压力层级，没有目标机器长时性能历史基线。
- 没有覆盖率报告归档、sanitizer CI 和静态分析策略。

优先补强：

1. 建立带版本、审批和趋势图的基准结果归档。
2. 在 CI 归档覆盖率、sanitizer、静态分析和 short/medium 报告。
3. 在目标部署机器运行 long 层并建立资源预算。

## 4. 本项目的优势

本项目不应直接追求“成为 FlightGear/X-Plane/MSFS”。它更适合做小而可控的闭环
验证平台，优势如下：

- 双进程闭环天然贴近 SIL：环境和飞控通过协议交互，而不是函数直连。
- 协议显式固定小端、版本、实例号和 CRC，便于日志回放和跨进程调试。
- 运行 manifest 保存 Git/构建身份、配置 CRC32/字节快照、资源版本和模型包线，
  比普通演示项目更容易审计一次结果的来源。
- 多实例隔离明确，适合 Monte Carlo 和故障注入。
- 代码规模可控，适合非敏感模型开发、架构实验和可审计回归。
- 不依赖大型商业工具链，能在普通 Linux/CMake 环境中构建和测试。

## 5. 不应宣称的能力

为了避免误用，文档和对外描述不应宣称：

- 武器级或适航级仿真。
- 已验证真实型号气动/推进/控制律。
- 已具备真实飞行器 HIL 接入能力。
- 已拥有全球真实地形、天气和场景资产。
- 可替代 JSBSim、FlightGear、X-Plane、Aerospace Blockset 或 STK。

更准确的表述是：

```text
这是一个 C11/CMake 实现、具备 V0-V5 自动证据的飞控-环境双进程软件在环工程基线，
具备可替换环境模型、完整工程故障矩阵、固定线协议、日志回放、多实例批量运行和
6DOF 主链路，可用于非敏感模型开发与回归；目标型号结论仍需 V6 相关性和 V7 HIL/试验。
```

## 6. 后续路线建议

短期：

- 导入非敏感目标外形气动与质量属性数据，建立 V6 对照场景。
- 在目标机器运行 128 实例和长时资源基准。
- 建立基准结果归档与 CI 报告。

中期：

- 协议 v2 的独立传感器时间戳和非锁步通信语义。
- 真实器件标定、总线适配和 HIL 接口边界。
- 权威风场/天气数据和完整任务区域地图资源。

长期：

- 与 JSBSim/FlightGear 做一条非敏感对照场景。
- 增加 HIL 接口抽象，但不接真实硬件默认实现。
- 复杂 surrogate 离线训练流水线和模型审计。
- 分布式实例管理和资源调度。
